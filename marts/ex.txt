the root-level `marts/` folder.

2. The extracted application includes:

   - `/marts/api/...` reaches the private Marts REST API
   - `/marts/ws/...` reaches the private Marts WebSocket API

   Production keeps the private service port at `8090`; the Replit development

VPS DEPLOYMENT AND SERVICE
==========================

The production Marts service is separate from AllMart. Both applications may
share the same VPS, domain, Nginx, HTTPS certificate, and Linux deployment user,
but Marts must keep its own database connection, environment file, Python
environment, process, logs, and restart commands.

Production layout:

    /opt/allmart/
    ├── ... existing AllMart files ...
    └── marts/
        ├── frontend/
        ├── src/
        ├── scripts/
        ├── .venv/
        ├── .env
        └── requirements.txt

The public URL is:

    https://YOUR_DOMAIN/marts/

The private Marts service listens only on:

    127.0.0.1:8090

Do not expose port 8090 through the VPS firewall. Nginx is the only public
entry point.


1. VPS PREREQUISITES
--------------------

Run the following as the deployment user with sudo access. The user should be
the same non-root user that owns `/opt/allmart`, for example `allmart`.

    sudo apt-get update
    sudo apt-get install -y python3 python3-venv python3-pip nodejs npm nginx curl

Only ports 22, 80, and 443 should be allowed in the provider firewall and UFW:

    sudo ufw default deny incoming
    sudo ufw default allow outgoing
    sudo ufw allow 22/tcp
    sudo ufw allow 80/tcp
    sudo ufw allow 443/tcp
    sudo ufw enable
    sudo ufw status

The Marts PostgreSQL database must already exist and must be separate from the
AllMart database. Do not point `MARTS_DATABASE_URL` at the AllMart database.


2. DEPLOY THE CODE
------------------

From the existing AllMart checkout:

    cd /opt/allmart
    git pull origin main
    sudo chown -R allmart:allmart /opt/allmart
    cd /opt/allmart/marts

Create a Marts-only Python environment:

    python3 -m venv .venv
    . .venv/bin/activate
    python -m pip install --upgrade pip
    python -m pip install -r requirements.txt
    deactivate

Install and build the production frontend:

    cd /opt/allmart/marts/frontend
    npm ci
    npm run build
    cd /opt/allmart/marts

The build must create:

    /opt/allmart/marts/frontend/dist/index.html

The Vite base path is `/marts/`. Do not deploy this frontend with `/` as its
base path or its assets will incorrectly request `/assets/...` instead of
`/marts/assets/...`.


3. CREATE THE MARTS ENVIRONMENT
-------------------------------

Create the file:

    sudo nano /opt/allmart/marts/.env

At minimum, configure:

    MARTS_DATABASE_URL=postgresql://MARTS_DB_USER:MARTS_DB_PASSWORD@DB_HOST:5432/marts
    MARTS_JWT_SECRET=GENERATED_LONG_RANDOM_SECRET
    MARTS_APP_URL=https://YOUR_DOMAIN
    MARTS_CORS_ALLOW_ORIGINS=https://YOUR_DOMAIN
    MARTS_ENVIRONMENT=production

Optional Marts integrations must use only the names in
`marts/.env.example`, such as `MARTS_OPENAI_API_KEY`,
`MARTS_ALPACA_API_KEY`, `MARTS_SMTP_HOST`, or
`MARTS_TELEGRAM_BOT_TOKEN`. Do not copy AllMart secrets into this file.

Generate a JWT secret on the VPS without putting it in shell history:

    python3 -c 'import secrets; print(secrets.token_urlsafe(48))'

If the optional admin seed is enabled, also set `MARTS_ADMIN_EMAIL` and
`MARTS_ADMIN_PASSWORD`, then change the password after the first successful
login. Never commit `.env`.

Protect the file:

    sudo chown allmart:allmart /opt/allmart/marts/.env
    sudo chmod 600 /opt/allmart/marts/.env

Validate the required variables:

    cd /opt/allmart/marts
    set -a
    . ./.env
    set +a
    bash scripts/check-env.sh

The check must report that the Marts environment variables are present. If no
dedicated `MARTS_DATABASE_URL` is available, the code allows `DATABASE_URL` as
an explicit fallback, but production should use the dedicated variable.


4. TEST MARTS BEFORE NGINX
--------------------------

Run the service temporarily as the deployment user:

    cd /opt/allmart/marts
    set -a
    . ./.env
    set +a
    .venv/bin/python -m uvicorn src.api.main:app \
      --host 127.0.0.1 --port 8090

In a second SSH session, test:

    curl --fail --silent --show-error http://127.0.0.1:8090/api/health
    curl --fail --silent --show-error http://127.0.0.1:8090/marts/
    curl --silent --output /dev/null --write-out '%{http_code}\n' \
      http://127.0.0.1:8090/api/users/me

Expected results:

    /api/health       -> HTTP 200 with "db": true
    /marts/           -> HTTP 200 serving the frontend
    /api/users/me     -> HTTP 401 without credentials

Stop the temporary process with Ctrl+C after the checks pass.


5. INSTALL THE SYSTEMD SERVICE
-------------------------------

Create `/etc/systemd/system/marts.service`:

    sudo nano /etc/systemd/system/marts.service

Use:

    [Unit]
    Description=Marts financial intelligence service
    After=network-online.target
    Wants=network-online.target

    [Service]
    Type=simple
    User=allmart
    Group=allmart
    WorkingDirectory=/opt/allmart/marts
    EnvironmentFile=/opt/allmart/marts/.env
    Environment="PATH=/opt/allmart/marts/.venv/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin"
    ExecStart=/opt/allmart/marts/scripts/start.sh
    Restart=on-failure
    RestartSec=5
    NoNewPrivileges=true
    PrivateTmp=true

    [Install]
    WantedBy=multi-user.target

The startup script reads `MARTS_PORT` when provided and defaults to 8090.
Because the service has the virtual environment first in `PATH`, its
`python3 -m uvicorn` command uses the Marts environment.

Enable and start the independent service:

    sudo systemctl daemon-reload
    sudo systemctl enable marts
    sudo systemctl start marts
    sudo systemctl status marts --no-pager

Verify the service and database:

    cd /opt/allmart/marts
    set -a
    . ./.env
    set +a
    bash scripts/health-check.sh

View Marts logs:

    sudo journalctl -u marts -n 100 --no-pager
    sudo journalctl -u marts -f

Marts can be restarted without restarting AllMart:

    sudo systemctl restart marts
    sudo systemctl is-active marts

AllMart remains separately managed:

    sudo systemctl restart allmart
    sudo systemctl is-active allmart


6. ADD NGINX ROUTING
--------------------

Keep the existing AllMart locations unchanged, then add the Marts locations to
the same HTTPS server block. Replace `YOUR_DOMAIN` with the real domain.

    # Prevent /marts from falling through to the AllMart frontend.
    location = /marts {
        return 301 /marts/;
    }

    location /marts/api/ {
        proxy_pass http://127.0.0.1:8090/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    location /marts/ws/ {
        proxy_pass http://127.0.0.1:8090/api/ws/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    location /marts/ {
        proxy_pass http://127.0.0.1:8090/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

The `/marts/api/` location must appear before the general `/marts/` location.
The trailing slash in `proxy_pass http://127.0.0.1:8090/` intentionally removes
the public `/marts` prefix before the request reaches FastAPI.

Test and reload without stopping either application:

    sudo nginx -t
    sudo systemctl reload nginx


7. HTTPS AND PUBLIC CHECKS
--------------------------

Point the domain's DNS records to the VPS, then obtain a certificate:

    sudo apt-get install -y certbot python3-certbot-nginx
    sudo certbot --nginx -d YOUR_DOMAIN -d www.YOUR_DOMAIN
    sudo nginx -t
    sudo systemctl reload nginx
    sudo certbot renew --dry-run

Verify from an external machine:

    curl --fail --silent --show-error https://YOUR_DOMAIN/marts/
    curl --fail --silent --show-error https://YOUR_DOMAIN/marts/api/health
    curl --silent --output /dev/null --write-out '%{http_code}\n' \
      https://YOUR_DOMAIN/marts/api/users/me

Expected results:

    https://YOUR_DOMAIN/marts/              -> HTTP 200
    https://YOUR_DOMAIN/marts/api/health    -> HTTP 200
    protected API without a session         -> HTTP 401

Confirm the private port is not publicly bound:

    sudo ss -tlnp

Expected:

    127.0.0.1:8090  -> Marts only
    *:80            -> Nginx
    *:443           -> Nginx

There should be no public `0.0.0.0:8090` listener and no firewall rule opening
8090.
