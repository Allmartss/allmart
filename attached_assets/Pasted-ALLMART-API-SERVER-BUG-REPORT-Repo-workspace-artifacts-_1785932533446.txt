==================================================
CRITICAL (6)
==================================================

C1. Authentication is client-side: nb_user cookie is the user ID, unsigned.
    File: artifacts/api-server/src/lib/auth.ts:7-13
    Code: getUserFromCookie reads req.cookies["nb_user"], Number(), SELECT users WHERE id = n
    Impact: Anyone can set nb_user=1 in a cookie and become admin. No token, JWT, HMAC,
    session record, or link to nb_session. Compromises every protected endpoint.
    Repro: curl -H "Cookie: nb_user=1" /api/orders → admin's orders.

C2. Unauthenticated file upload serves user-controlled SVG → stored XSS.
    File: artifacts/api-server/src/routes/storage.ts:47-88, 97-142, 160, 176-212
    Code: detectMimeType returns "image/svg+xml" when first byte is "<"; serveLocalFile
    sets that content-type with Cache-Control: public, max-age=31536000, immutable and
    no Content-Disposition: attachment. POST /storage/uploads/request-url and PUT
    /storage/local/:uuid have no auth.
    Impact: Attacker uploads <svg onload=...> → same-origin XSS in any logged-in admin's
    browser; payload persists in HTTP cache for a year.
    Repro: PUT /api/storage/local/<uuid> with body starting `<svg onload=...>` → visit
    /api/storage/local/<uuid> as admin.

C3. HTML-injection in support-ticket forward email → XSS in admin's mail client.
    File: artifacts/api-server/src/routes/support.ts:19-30
    Code: `html: `<p>From: ${name} <${email}></p><p>${message.replace(/\n/g,"<br>")}</p>``
    Impact: name and message are interpolated into HTML with no escHtml. Admin reading
    forwarded ticket in a webmail client triggers the payload.
    Repro: POST /api/support-tickets with name="<img src=x onerror=...>".

C4. Stripe callbackUrl from request body, no allowlist.
    File: artifacts/api-server/src/routes/stripe.ts:13
    Code: success_url is built from req.body.callbackUrl with no host check.
    Impact: Shopper pays full amount, browser is redirected to attacker with
    ?session_id=cs_test_...; attacker replays the id at /stripe/verify and captures
    the order.

C5. Stripe amount from request body, no comparison to cart subtotal.
    File: artifacts/api-server/src/routes/stripe.ts:13
    Code: unit_amount = Math.round(req.body.amount * 100); no comparison to cart total.
    Impact: Shopper pays $1 on a $200 cart.
    Repro: POST /api/stripe/initialize {amount: 1} on $200 cart.

C6. /stripe/verify is unauthenticated and accepts shippingAddress override.
    File: artifacts/api-server/src/routes/stripe.ts:55-109
    Code: No auth middleware; reads shippingAddress from req.body and uses it to place
    order against whichever sessionId is in Stripe metadata.
    Impact: Combined with C4/C5, an unauthenticated attacker who obtains any Stripe
    session id redirects shipment of the paid cart to themselves.

==================================================
CROSS-CUTTING / RECURRING PATTERNS
==================================================

- Read-then-write races everywhere (cashback, bonus, cart, ratings, refunds,
  gifts, referral claim). Need: row-level locks, conditional UPDATEs, or
  transactions.
- Zod parsing skipped on most admin/write routes. req.body as {…} casts everywhere.
- No global Express error middleware (app.ts has no use((err,req,res,next)=>...));
  process.on('unhandledRejection') and 'uncaughtException' not registered.
- No Stripe webhook handler anywhere; no express.raw body parser for it.
- cors() called with no options → wildcard Access-Control-Allow-Origin.
- express.json({limit:"5mb"}) is global; chat can hit it legitimately and 413
  silently breaks mid-checkout.
- nb_session cookie never rotated on sign-in/out; sameSessionId across users
  on shared browser is the root of multiple "ownership" bugs.
