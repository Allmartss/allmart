AllMart — VPS Deployment & Cloudflare Domain Guide
=====================================================

This guide covers deploying AllMart on a fresh VPS (Ubuntu 22.04/24.04)
and connecting it to a custom domain via Cloudflare.


═══════════════════════════════════════════════════════════════
PART 1 — SERVER PREPARATION
═══════════════════════════════════════════════════════════════

Step 1: Create a VPS
─────────────────────
  • Any provider works (Hetzner, DigitalOcean, Vultr, Linode, etc.)
  • Recommended minimum: 2 vCPU, 2 GB RAM, 20 GB SSD
  • OS: Ubuntu 22.04 LTS or 24.04 LTS
  • Open ports in your provider's firewall: 22 (SSH), 80 (HTTP), 443 (HTTPS)

Step 2: SSH into the server
────────────────────────────
  ssh root@YOUR_SERVER_IP

Step 3: Install Node.js 24
───────────────────────────
  curl -fsSL https://deb.nodesource.com/setup_24.x | bash -
  apt-get install -y nodejs

  Verify:
    node -v   # should print v24.x.x

Step 4: Install pnpm
─────────────────────
  npm install -g pnpm
  pnpm -v   # should print 9.x or later

Step 5: Install PostgreSQL
───────────────────────────
  Option A — Use Supabase (recommended, no server config needed):
    Create a free project at https://supabase.com
    Copy the "Connection string" (URI format) from Project Settings → Database
    Use it as SUPABASE_DB_URL / DATABASE_URL in your .env

  Option B — Install PostgreSQL locally:
    apt-get install -y postgresql postgresql-contrib
    systemctl enable --now postgresql
    sudo -u postgres psql -c "CREATE DATABASE allmart;"
    sudo -u postgres psql -c "CREATE USER allmart WITH PASSWORD 'strongpassword';"
    sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE allmart TO allmart;"
    # Connection string: postgres://allmart:strongpassword@localhost:5432/allmart

Step 6: Install git
────────────────────
  apt-get install -y git


═══════════════════════════════════════════════════════════════
PART 2 — DEPLOY THE APPLICATION
═══════════════════════════════════════════════════════════════

Step 7: Clone the repository
─────────────────────────────
  cd /opt
  git clone https://github.com/YOUR_ORG/allmart.git
  cd allmart

Step 8: Create the environment file
─────────────────────────────────────
  cp .env.example .env    # if .env.example exists
  nano .env               # edit with your values

  Required variables:
    DATABASE_URL=postgres://allmart:strongpassword@localhost:5432/allmart
    # (or your Supabase connection string)
    SUPABASE_DB_URL=postgres://...   # same as DATABASE_URL if using Supabase
    SESSION_SECRET=<random 32+ char string>
    PORT_API=8080

  Optional — S3-compatible file storage (images):
    FILE_ENDPOINT_URL=https://...
    FILE_BUCKET=your-bucket-name
    FILE_ACCESS_KEY_ID=your-key
    FILE_SECRET_ACCESS_KEY=your-secret
    FILE_REGION=auto

  Optional — AI features:
    GROQ_API_KEY=gsk_...
    NVIDIA_API_KEY=nvapi-...

  Optional — Email (SMTP or Resend):
    SMTP_HOST=smtp.example.com
    SMTP_PORT=587
    SMTP_USER=user@example.com
    SMTP_PASSWORD=yourpassword

  Optional — Telegram bot:
    TELEGRAM_BOT_TOKEN=7123456789:AAF...
    TELEGRAM_CHAT_ID=-100123456789
    TELEGRAM_WEBHOOK_SECRET=any-random-string

  Optional — Payments:
    STRIPE_SECRET_KEY=sk_live_...
    STRIPE_WEBHOOK_SECRET=whsec_...

Step 9: Install dependencies
──────────────────────────────
  pnpm install

Step 10: Push the database schema
───────────────────────────────────
  pnpm --filter @workspace/db run push

  This applies all tables and columns to your database without destroying data.

Step 11: Seed the admin user
──────────────────────────────
  pnpm --filter @workspace/scripts run seed-admin

  Note the printed admin credentials — change the password after first login.

Step 12: Build the application
────────────────────────────────
  pnpm --filter @workspace/api-server run build
  pnpm --filter @workspace/storefront run build

Step 13: Test the server manually
───────────────────────────────────
  bash start.sh

  Visit http://YOUR_SERVER_IP:8080 in a browser to confirm it works.
  Press Ctrl+C to stop after confirming.

Step 14: Set up a systemd service (keeps the app running)
───────────────────────────────────────────────────────────
  Create the service file:
    nano /etc/systemd/system/allmart.service

  Paste this (adjust paths/user as needed):

    [Unit]
    Description=AllMart
    After=network.target

    [Service]
    Type=simple
    User=root
    WorkingDirectory=/opt/allmart
    EnvironmentFile=/opt/allmart/.env
    ExecStart=/bin/bash /opt/allmart/start.sh
    Restart=on-failure
    RestartSec=10

    [Install]
    WantedBy=multi-user.target

  Enable and start:
    systemctl daemon-reload
    systemctl enable allmart
    systemctl start allmart
    systemctl status allmart    # should show "active (running)"

  View logs:
    journalctl -u allmart -f


═══════════════════════════════════════════════════════════════
PART 3 — INSTALL NGINX AS REVERSE PROXY
═══════════════════════════════════════════════════════════════

AllMart's API server runs on port 8080.  Nginx sits in front on port 80/443
and forwards requests to it, and also handles SSL termination.

Step 15: Install Nginx
───────────────────────
  apt-get install -y nginx
  systemctl enable --now nginx

Step 16: Create an Nginx site config
──────────────────────────────────────
  nano /etc/nginx/sites-available/allmart

  Paste:

    server {
        listen 80;
        server_name yourdomain.com www.yourdomain.com;

        client_max_body_size 50M;

        location / {
            proxy_pass         http://127.0.0.1:8080;
            proxy_http_version 1.1;
            proxy_set_header   Upgrade $http_upgrade;
            proxy_set_header   Connection 'upgrade';
            proxy_set_header   Host $host;
            proxy_set_header   X-Real-IP $remote_addr;
            proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header   X-Forwarded-Proto $scheme;
            proxy_cache_bypass $http_upgrade;
        }
    }

  Replace `yourdomain.com` with your actual domain.

  Enable the site:
    ln -s /etc/nginx/sites-available/allmart /etc/nginx/sites-enabled/
    nginx -t                   # test config — must say "ok"
    systemctl reload nginx


═══════════════════════════════════════════════════════════════
PART 4 — CLOUDFLARE DOMAIN SETUP
═══════════════════════════════════════════════════════════════

Step 17: Add your domain to Cloudflare
────────────────────────────────────────
  1. Sign up or log in at https://cloudflare.com
  2. Click "Add a Site" and enter your domain name.
  3. Choose the Free plan (sufficient for most use).
  4. Cloudflare will scan your existing DNS records.

Step 18: Update nameservers at your registrar
──────────────────────────────────────────────
  Cloudflare will show you two nameserver addresses, e.g.:
    aria.ns.cloudflare.com
    bob.ns.cloudflare.com

  Go to your domain registrar (Namecheap, GoDaddy, Google Domains, etc.)
  and replace the current nameservers with the Cloudflare ones.

  Propagation typically takes 5–30 minutes (up to 48h in rare cases).

Step 19: Add DNS records in Cloudflare
────────────────────────────────────────
  In the Cloudflare dashboard → DNS → Records, add:

    Type   Name    Content              Proxy status
    ────   ──────  ───────────────────  ────────────
    A      @       YOUR_SERVER_IP       Proxied (orange cloud)
    A      www     YOUR_SERVER_IP       Proxied (orange cloud)

  "Proxied" means traffic routes through Cloudflare (CDN + DDoS protection).

Step 20: Set SSL/TLS mode in Cloudflare
────────────────────────────────────────
  Cloudflare → SSL/TLS → Overview → set mode to "Full (strict)"

  This requires a real certificate on your server (done in the next step).
  If you skip the cert step, use "Full" (not strict) temporarily.

Step 21: Install a free SSL certificate (Let's Encrypt)
─────────────────────────────────────────────────────────
  apt-get install -y certbot python3-certbot-nginx

  Obtain a certificate:
    certbot --nginx -d yourdomain.com -d www.yourdomain.com

  Follow the prompts (enter email, agree to terms).
  Certbot will automatically update your Nginx config for HTTPS.

  Auto-renewal is set up automatically. Test it with:
    certbot renew --dry-run

Step 22: Reload Nginx
──────────────────────
  nginx -t && systemctl reload nginx

  Your site should now be live at https://yourdomain.com


═══════════════════════════════════════════════════════════════
PART 5 — POST-DEPLOYMENT TASKS
═══════════════════════════════════════════════════════════════

Step 23: Register the Telegram webhook (if using Telegram bot)
───────────────────────────────────────────────────────────────
  1. Ensure TELEGRAM_BOT_TOKEN and TELEGRAM_WEBHOOK_SECRET are set in .env
  2. Log in to AllMart admin panel → Telegram Bot → "Register webhook"
  3. The webhook URL will be: https://yourdomain.com/api/telegram/webhook

Step 24: Configure Stripe webhook (if using payments)
───────────────────────────────────────────────────────
  1. Go to https://dashboard.stripe.com/webhooks
  2. Add endpoint: https://yourdomain.com/api/stripe/webhook
  3. Select events: payment_intent.succeeded, checkout.session.completed
  4. Copy the signing secret → add as STRIPE_WEBHOOK_SECRET in .env
  5. Restart the service: systemctl restart allmart

Step 25: Set up hourly database backups
─────────────────────────────────────────
  crontab -e

  Add this line:
    0 * * * * cd /opt/allmart && pnpm --filter @workspace/scripts run backup >> /tmp/backup.log 2>&1

  Verify:
    tail -f /tmp/backup.log

PART 7 — CLOUDFLARE PERFORMANCE TIPS (optional)
═══════════════════════════════════════════════════════════════

• Speed → Optimization → enable "Auto Minify" (HTML, CSS, JS)
• Caching → Configuration → set "Browser Cache TTL" to 1 day
• Speed → Optimization → enable "Rocket Loader" (may conflict with some JS)
• Security → Settings → set "Security Level" to Medium
• Rules → Page Rules → cache static assets:
    Pattern: yourdomain.com/assets/*
    Setting: Cache Level = Cache Everything, Edge TTL = 1 month

PART 8 — VPS SECURITY HARDENING (do this before running anything)
═══════════════════════════════════════════════════════════════

Do these steps immediately after you get SSH access to your fresh VPS,
before installing Node, Nginx, or AllMart.


────────────────────────────────────────────────────────────────
STEP A — Create a non-root user
────────────────────────────────────────────────────────────────
Running everything as root is dangerous. Create a regular user instead.

  adduser allmart
  # enter a strong password when prompted

  usermod -aG sudo allmart
  # gives the user sudo access when needed

Switch to that user for all future work:
  su - allmart
  # or reconnect via SSH as: ssh allmart@YOUR_SERVER_IP


────────────────────────────────────────────────────────────────
STEP B — Set up SSH key login (disable password login)
────────────────────────────────────────────────────────────────
On YOUR local machine (not the server), generate a key pair if you don't
have one:
  ssh-keygen -t ed25519 -C "your@email.com"
  # press Enter to accept defaults

Copy your public key to the server:
  ssh-copy-id allmart@YOUR_SERVER_IP
  # enter the user password one last time

Test that key login works (open a new terminal):
  ssh allmart@YOUR_SERVER_IP
  # should log in without asking for a password

Now disable password authentication on the server:
  sudo nano /etc/ssh/sshd_config

  Find and set these lines (add them if missing):
    PermitRootLogin no
    PasswordAuthentication no
    PubkeyAuthentication yes

  Save the file, then restart SSH:
    sudo systemctl restart sshd

  IMPORTANT: keep your current SSH session open while testing the new
  connection in a second terminal — if you lock yourself out you can
  still fix it from the open session.


────────────────────────────────────────────────────────────────
STEP C — Configure the firewall (UFW)
────────────────────────────────────────────────────────────────
Only allow the ports AllMart actually needs.

  sudo apt-get install -y ufw

  sudo ufw default deny incoming
  sudo ufw default allow outgoing

  sudo ufw allow 22/tcp      # SSH
  sudo ufw allow 80/tcp      # HTTP  (Nginx + Cloudflare)
  sudo ufw allow 443/tcp     # HTTPS (Nginx + Cloudflare)

  sudo ufw enable            # type "y" to confirm
  sudo ufw status            # verify the rules

NOTE: do NOT open port 8080 (AllMart's internal API port).
Nginx proxies all traffic to it internally — it should never be
exposed directly to the internet.

If you use Cloudflare proxy (orange cloud), you can optionally
restrict port 80/443 to Cloudflare's IP ranges only. See:
  https://www.cloudflare.com/ips/


────────────────────────────────────────────────────────────────
STEP D — Enable automatic security updates
────────────────────────────────────────────────────────────────
Keep the OS patched automatically without manual intervention.

  sudo apt-get install -y unattended-upgrades
  sudo dpkg-reconfigure --priority=low unattended-upgrades
  # select "Yes" when prompted

Verify it is active:
  sudo systemctl status unattended-upgrades


────────────────────────────────────────────────────────────────
STEP E — Install Fail2Ban (block brute-force attacks)
────────────────────────────────────────────────────────────────
Fail2Ban watches logs and bans IPs that repeatedly fail SSH login.

  sudo apt-get install -y fail2ban

  sudo nano /etc/fail2ban/jail.local

  Paste this:

    [sshd]
    enabled   = true
    port      = 22
    maxretry  = 5
    bantime   = 1h
    findtime  = 10m

  Save, then start the service:
    sudo systemctl enable --now fail2ban
    sudo fail2ban-client status sshd    # verify it is watching SSH


────────────────────────────────────────────────────────────────
STEP F — Secure shared memory
────────────────────────────────────────────────────────────────
Mount /run/shm read-only to prevent a class of privilege-escalation attacks.

  sudo nano /etc/fstab

  Add this line at the bottom:
    tmpfs /run/shm tmpfs defaults,noexec,nosuid 0 0

  Apply without rebooting:
    sudo mount -o remount /run/shm


────────────────────────────────────────────────────────────────
STEP G — Harden Nginx
────────────────────────────────────────────────────────────────
Add these lines inside the http { } block in /etc/nginx/nginx.conf
(before the include lines at the bottom):

  sudo nano /etc/nginx/nginx.conf

  Add inside http { }:

    # Hide Nginx version from error pages and headers
    server_tokens off;

    # Prevent clickjacking
    add_header X-Frame-Options SAMEORIGIN;

    # Prevent MIME-type sniffing
    add_header X-Content-Type-Options nosniff;

    # Enable XSS filter in older browsers
    add_header X-XSS-Protection "1; mode=block";

    # Only send referrer on same origin
    add_header Referrer-Policy "strict-origin-when-cross-origin";

    # Limit request body size (matches AllMart's file upload limit)
    client_max_body_size 50M;

  Test and reload:
    sudo nginx -t && sudo systemctl reload nginx


────────────────────────────────────────────────────────────────
STEP H — Protect the .env file
────────────────────────────────────────────────────────────────
The .env file contains your database password, session secret, and API keys.
Restrict who can read it.

  chmod 600 /opt/allmart/.env
  chown allmart:allmart /opt/allmart/.env

Only the allmart user (and root) can now read it.


────────────────────────────────────────────────────────────────
STEP I — Check for open ports (verify your setup)
────────────────────────────────────────────────────────────────
After everything is configured, confirm only expected ports are listening:

  sudo ss -tlnp

  You should see ONLY:
    *:22    — SSH (sshd)
    *:80    — HTTP (nginx)
    *:443   — HTTPS (nginx)
    127.0.0.1:8080 — AllMart API (local only, not exposed)

  If port 8080 shows 0.0.0.0:8080 (all interfaces), something is wrong —
  check your UFW rules and AllMart's PORT_API binding.

────────────────────────────────────────────────────────────────

  [ ] UFW firewall active — only ports 22, 80, 443 open
  [ ] Port 8080 NOT exposed publicly
  [ ] Automatic security updates enabled
  [ ] Fail2Ban installed and watching SSH
  [ ] /etc/nginx/nginx.conf hardened (server_tokens off, security headers)
